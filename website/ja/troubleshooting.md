# トラブルシューティング

*問題に直面したとき、既存の計画やデータを失わずに原因を特定して復旧するためのガイドです。*

## 1. Plugin を導入できない

- **確認すること:** 対応 OS/アーキテクチャ（macOS `arm64`/`x86_64`、Linux `x86_64`/`arm64`）、クライアントのバージョン、`https://github.com/FooQoo/agent-flow-kit.git` への通信可否を確認します。
- **解決手順:** [インストール](/ja/guide/installation) のコマンドを再実行します。ネットワーク制限がある環境では [GitHub Releases](https://github.com/FooQoo/agent-flow-kit/releases) のオフライン向けアーカイブを利用してください。
- **正常な状態:** クライアントのプラグイン一覧に `agent-flow-kit` が表示され、`/agent-flow-kit:afk`（Claude Code）または `$agent-flow-kit:afk`（Codex）が利用できます。
- **解決しない場合:** OS・クライアント版・エラー出力を添えて [GitHub Issues](https://github.com/FooQoo/agent-flow-kit/issues) へ報告してください。

## 2. MCP が起動しない

- **確認すること:** 各バージョンの初回起動時、`run` が GitHub Releases からアーカイブと `SHA256SUMS` を取得します。`curl` または `wget`、`tar`、`shasum` / `sha256sum` が使えること、および `github.com` へ接続できることを確認します。
- **解決手順:** クライアントの MCP stderr ログでダウンロード失敗や SHA256 不一致が出ていないか確認します。オフライン環境では GitHub Releases のバイナリ同梱アーカイブを使い、`run` と同階層に `bin/afk-*` を配置します。
- **正常な状態:** クライアントに 6 つの AFK ツール（`record_request`, `open_plan`, `update_plan`, `update_question`, `start_next`, `finish_task`）が認識されます。
- **解決しない場合:** 秘匿情報を除いた stderr ログを GitHub Issues で共有してください。

## 3. AI が AFK を使わない

- **確認すること:** プラグインが有効になっているか、インストール後に **新しいセッション** を開いたか、`/agent-flow-kit:afk` または `$agent-flow-kit:afk` を使って呼び出したかを確認します。
- **解決手順:** 新しいセッションを開き、他に入れている Skill と指示が競合していないか確認します（Skill は行動指針であり、すべてのターンで強制的に呼ばれるものではありません）。
- **正常な状態:** エージェントが `record_request` や `open_plan` を呼び、`.afk/` にファイルを保存・参照します。
- **解決しない場合:** まずクライアントのツール一覧に 6 つの MCP ツールが見えているか確認してください。

## 4. 計画・タスクが進まない

- **確認すること:** `open_plan` の `progress.next` を確認します。よくある待機理由は以下のとおりです。
  - `wait_for_answer`: 未回答の質問がある。
  - `await_start`: 計画のみ確定した `Backlog` 状態で開始指示待ち。
  - `replan`: 追加依頼や回答済み質問がまだ新リビジョンに確定されていない。
  - 前提タスクが未完了、または `## Acceptance` / `## Result` が不足している。
- **解決手順:** 質問に回答する、「進めて」と開始を指示する、または保留中の改訂を確定させます。
- **正常な状態:** `progress.next` が `start_task`・`resume_task`・`verify_plan` のいずれかになります。
- **解決しない場合:** `.afk/plans/` と `.afk/questions/` の中身を直接確認してください。

## 5. 進捗が表示されない

- **確認すること:** クライアントの Hook が有効・信頼済みか確認します（Codex では `PostToolUse` と `Stop` の信頼許可が必要です）。なお、進捗報告は特定のプランを操作したターンでのみ表示され、`plan_id` なしの `open_plan` や `codex exec --json` のような非対話ストリームでは表示されません。
- **解決手順:** Hook の信頼設定を確認し、一度 MCP ツールが動いてバイナリがキャッシュされた状態か確認します（未キャッシュ時の `--hook` は 1 秒タイムアウトを避けるため静かに `exit 0` します）。
- **正常な状態:** AFK ツールを使ったターンの末尾に `AFK · <タイトル> [<状態>] · ...` が表示されます。
- **解決しない場合:** `PLUGIN_DATA` / `CLAUDE_PLUGIN_DATA` ディレクトリに書き込み権限があるか確認してください。

## 6. 再開できない

- **確認すること:** `.afk/` がある **同じプロジェクトルート** で新しいセッションを開いているか確認します。`a different session owns this task` が出る場合は、前のセッションが `Doing` のまま終了しています。
- **解決手順:** 前のセッションが完全に停止していることを確認したうえで、`open_plan`（`tasks: true`）で引き継ぎメモを確認し、`start_next`（`take_over: true`）で引き継ぎます。`AFK_NEEDS_WORKSPACE=1` 環境では初回呼び出しに絶対パスを渡す必要があります。
- **正常な状態:** `open_plan` が前回のプラン・引き継ぎメモ・残タスクを返します。
- **解決しない場合:** `.afk/` の権限（既定 `0700`）を確認してください。

## 7. データの整合性が崩れた（`confirmed text changed` やドラフト欠損）

- **確認すること:** `.afk/` 内の手動編集を一旦止めます。**無条件に `.afk/afk.db` を削除しないでください。** まず AFK が動いていない状態で `.afk/` フォルダ全体を別場所へバックアップします。
- **解決手順:**
  - 確定前のドラフトファイルが欠けている場合は、公開中の `draft_id` で `update_plan / recover` を実行します。
  - 確定済みのプランやタスク `.md` を直接編集してしまった場合は、変更内容を `.afk/` の外へ控え、元の確定テキストに戻してから新しいドラフト（`prepare` + `commit`）で改訂します。
  - DB 未参照の孤立 `.md` ファイルは `open_plan`（`check_files: true`）で確認できます。
- **正常な状態:** `open_plan` がハッシュ不一致やファイル欠損エラーなく返ります。
- **解決しない場合:** バックアップを保持したまま、正確なエラーメッセージを添えて GitHub Issues へ相談してください。

## 8. 更新後に動かない

- **確認すること:** クライアントが新しいプラグイン版を読み込んでいるか、対応バージョンのバイナリ（`v<version>/`）が取得されているか確認します。
- **解決手順:** クライアントのセッションを再起動して新しい MCP プロセスを立ち上げます。ダウンロード途中で失敗していた場合はキャッシュ内の該当バージョンフォルダを削除して再起動してください。
- **正常な状態:** 新セッションでエラーなく起動し、`open_plan` で既存プランが読めます。
- **解決しない場合:** [GitHub Releases](https://github.com/FooQoo/agent-flow-kit/releases) のリリースノートを確認してください。

## 9. トークン消費が多い

- **確認すること:** 1 つのセッションが長くなりすぎている、タスク文書が肥大化している、あるいは AFK 以外の大きなコンテキストが溜まっている可能性があります。
- **解決手順:** タスク単位を簡潔に保ち、別件は別プランに分け、会話が長くなったら `/agent-flow-kit:afk handoff`（Codex は `$agent-flow-kit:afk` + `handoff`）で引き継ぎメモを残して新しいセッションへ切り替えます。
- **正常な状態:** セッションが現行プランと対象タスクに絞られた状態で進行します。

## 10. バグを報告したい

[GitHub Issues](https://github.com/FooQoo/agent-flow-kit/issues) に起票する際は、以下を記載してください。

- AFK のバージョン、利用クライアント名とバージョン（Claude Code / Codex 等）、OS とアーキテクチャ
- 再現手順、期待した挙動、実際の挙動
- エラーメッセージやログ（**機密情報・個人のパス・社内コードなどは必ず除去してください**）
