# 既存の手法・ツールとの違い（Positioning）

*他の AI 開発手法やタスク管理ツールと AFK の違い・使い分けを整理したい方向けのページです。*

> Agent Flow Kit は、AI の仕事の遂行を支えるハーネスです。ソフトウェア開発の方法論や、タスクの共有・管理を中心としたツールとは、設計の起点が異なります。ただし、計画やタスク、レビューなど共通する機能はあり、用途によって使い分けられます。

## A. AI 駆動開発系：AI-DLC / SDD / Spec Kit

- **[AI-DLC Workflows](https://awslabs.github.io/aidlc-workflows/guide/00-introduction/)**: AI を活用するソフトウェア開発を再現可能な工程へ整理する方法論とその実装。既存の CLI ハーネス内で動く仕組みも備えています。
- **SDD（Spec-Driven Development）**: 仕様を起点に開発を進めるアプローチ。
- **[GitHub Spec Kit](https://github.github.com/spec-kit/index.html)**: SDD を含む開発プロセスのツールキット。単なる仕様テンプレートにとどまらず、プロセスハーネスとしての機能も備えています。

| 観点 | AI-DLC / SDD（一般的な主眼） | AFK（設計方針） |
| --- | --- | --- |
| 目的 | AI を使ったソフトウェア開発の工程・仕様を整える | AI による仕事の遂行を支える |
| 中心概念 | 開発フェーズ・仕様・開発成果物 | Request / Plan / Task / Question |
| 適用範囲 | 主としてソフトウェア開発 | 開発を起点に調査・文書作成などの仕事にも適用可能な設計 |
| 方法論 | 開発プロセスや仕様に関する具体的なガイド | 特定の開発方法論を前提としない |
| 人間の関与 | 工程のレビューや意思決定など、方法論によって異なる | 必要な質問、方向修正、進捗確認 |

**関係性:** AFK は AI-DLC や SDD を否定するものではなく、それらの方法論に従う仕事を扱う余地があります。ただし、Skill 間の競合・状態の二重管理・計画粒度・承認境界の整合性は未検証のため、現時点では公式連携や互換性を保証していません。

## B. ボード・タスク管理系：Vercel Board / Backlog.md

- **[Vercel Board](https://github.com/vercel/board)**: チームとコーディングエージェントが、チャンネル・スレッド・タスクを通して仕事を共有・協調する仕組み。
- **[Backlog.md](https://github.com/MrLesk/Backlog.md)**: Git 環境で人間と AI の仕事を管理する Markdown 中心のツール。[Manifesto](https://github.com/MrLesk/Backlog.md/blob/main/MANIFESTO.md) でも計画・完了条件・記録・成果を明示的に管理する思想が示されており、AI 向けガイドやレビューの仕組みを含め AFK と重なる部分が大きいツールです。

| 観点 | Vercel Board | Backlog.md | AFK（設計方針） |
| --- | --- | --- | --- |
| 主な目的 | チーム・エージェントの仕事共有と協調 | タスク管理と人間・AI の協働 | AI の仕事の遂行支援 |
| 中心概念 | チャンネル・スレッド・タスク | タスク、計画、完了条件、履歴 | 依頼から完了までの進行 |
| 管理体験 | 共有の作業場 | タスクを明示的に管理できる | 通常の会話を主な操作面にする |
| 人間の関与 | 共有・対話・分担 | タスクやレビューを通じた関与 | 依頼・必要な判断・方向修正 |
| AFK が意図する差 | — | — | 専用管理 UI を必要とせず、既存エージェントの進め方を拡張する |

Backlog.md にも計画・完了条件・AI 向けルールがあるため、「他は管理するだけ、AFK だけが遂行を支える」と断定することはしません。主な違いは設計の重心と操作面にあります。

## C. ポジショニングの全体像

```text
  Human（目的・判断） <──▶ 既存の AI エージェント（Claude Code / Codex）
                               ├──▶ AFK（仕事の遂行支援ハーネス）
                               ├──▷ AI-DLC / SDD / Spec Kit（選択可能な開発方法論）
                               └──▷ Vercel Board / Backlog.md（必要に応じた仕事の共有・管理）
```

*※ 各製品・手法の主な役割を表す概念図であり、技術的な依存関係・公式連携・排他的な分類を示すものではありません。*

## まとめ

> 開発手法を押し付けない。管理画面を必須にしない。エージェントを置き換えない。ただ、AI の仕事の遂行を支える。
