# クイックスタート

このページでは **10分ほど** で1つの小さな作業を通して、Agent Flow Kit（AFK）の基本の動きを一通り試します。

1. 複数ステップの依頼を送る
2. `.afk/` に作られたファイルを見る
3. エージェントからの質問（`Q-001`）に答える
4. 計画だけ見る（`Backlog`）か、すぐ始める（`authorize`）かを知る
5. 作業の途中で条件（「空文字も弾いて」）を足す
6. 完了条件（`## Acceptance`）と結果（`## Result`）がどう確かめられるかを見る
7. セッションを閉じて、新しいセッションから続きを再開する

始める前に、[導入とセットアップ](getting-started.md) を見てクライアントに AFK をつなぎ、練習用の空フォルダを1つ開いてください。

---

## ステップ 1: 依頼を送る

プロジェクトで AFK を呼び出し、JSON ファイルとチェック用スクリプトの作成を頼みます。質問の動きを見るため、あえて「中身は私に聞いて決めて」と添えてみます。

- **Claude Code：**
  ```text
  /agent-flow-kit:afk サンプルの JSON ファイルと、中身を検査するスクリプト・テストを作って。JSON に入れる項目は私に聞いて決めて。
  ```
- **Codex：** `$agent-flow-kit:afk` を選んで同じ文章を送ります。
- **Antigravity / 汎用 MCP：** `afk` スキルで同じ文章を送ります。

エージェントはまず `record_request` を呼び、あなたの依頼をそのまま `.afk/requests/001.md` に書き残します。

---

## ステップ 2: `.afk/` に作られたファイルを見る

次にエージェントは、2つのタスクを持つ計画の下書き（`add: [[], [-1]]`＝1番目が終わってから2番目に進む順番）を用意し、さらに質問用のファイルも1つ作ります。

この時点で `.afk/` の中はこうなっています。

```text
.afk/
├── afk.db
├── requests/
│   └── 001.md          # あなたの依頼文
├── plans/
│   └── 001-r001.md     # プラン #1 の下書き #1
├── tasks/
│   ├── 001.md          # タスク #1（JSON ファイルの作成）
│   └── 002.md          # タスク #2（検査スクリプトとテスト・#1 のあと）
└── questions/
    └── 001.md          # JSON の項目を尋ねる質問ファイル
```

プランとタスクは `# `・`## Acceptance`・`## Result` だけが入ったひな形から始まり、エージェントが普通のファイル編集ツールで中身を書き込んでいきます。

---

## ステップ 3: 質問（`Q-001`）に答える

勝手に JSON の形を決める代わりに、エージェントは `.afk/questions/001.md` に質問を書いて公開し、チャットであなたに尋ねます。

```markdown
# sample.json にはどの項目を入れますか？

好みの形を選んでください：
1. 文字列の `{ "id": "item-1", "value": "ready" }`
2. 数値を含む `{ "id": 1, "count": 42 }`

## Answer
```

未回答の質問がある間、AFK は作業の開始を止めます。もしエージェントが先に `start_next` を呼ぼうとしてもエラーになります。

チャットで答えを返します。

```text
両方とも文字列の { "id": "item-1", "value": "ready" } にして。
```

エージェントは `.afk/questions/001.md` の `## Answer` の下にあなたの答えを書き足して確定し、その内容を計画とタスクの本文に反映させて、計画の第1版を確定します（`commit`）。

---

## ステップ 4: 計画だけ見る（`Backlog`）か、すぐ始めるか

下書きを確定（`commit`）したあとの動きは、最初の頼み方で変わります。

| 最初の頼み方 | `commit` の指定 | 確定後の状態 | その後の動き |
| --- | --- | --- | --- |
| 「JSON と検査スクリプトを作って」（作業まで依頼） | `execute: true` | `Todo`（未着手） | すぐ `start_next` へ進み、タスク `#001` を始めます。 |
| 「まずは計画だけ立てて。作業はまだしないで」 | `execute: false` | `Backlog` | 開始待ちで止まります。作業に入る前に `.afk/plans/001-r001.md` や各タスクを落ち着いて読めます。 |

`Backlog` で待っている計画を動かしたいときは、チャットで声をかけます。

```text
計画を見ました。プラン #1 を始めて。
```

エージェントが `update_plan(authorize)` を呼ぶと、プランとタスクが `Todo` に移り、タスク `#001` が始まります。

---

## ステップ 5: 作業の途中で条件を足す

タスク `#001`（`fixtures/sample.json` の作成）が終わったあと、またはタスク `#002` の途中で、次の注文を足してみましょう。

```text
空文字やスペースだけの文字列もエラーにして。スペースだけのテストも追加して。
```

AFK は途中の変更を次の順番でさばきます。

1. **追加の依頼を残す：** エージェントが `record_request(plan_id: 1)` を呼び、`.afk/requests/002.md` に新しい注文を書きます。
2. **完了をいったん止める：** まだ計画に入れていない依頼がある間は、タスクやプランを完了にできなくなります（`next: replan`）。
3. **いまのタスクを確認する：** `open_plan(plan_id: 1, tasks: true)` を見て、`#001` が終わり、`#002` がまだ残っていることを確かめます。
4. **計画の第2版を確定する：** 未完了の `#002` を外し（`remove: [2]`）、終わった `#001` のあとに続く新しいタスク `#003` を追加（`add: [[1]]`）して、`001-r002.md` と `tasks/003.md` を確定します。

この確定で起きることはシンプルです。
- すでに終わったタスク `#001` は、結果も含めてそのまま残ります。
- 置き換えられた旧タスク `#002` は対象外（`retired`）になります（ファイル自体は記録として残ります）。
- 新しいタスク `#003` が未着手（`Todo`）として並び、`001-r002.md` がいまの計画（第2版）になります。

---

## ステップ 6: 完了条件と `## Result` を確かめる

エージェントは `start_next` でタスク `#003` を始め（`attempt: 1`）、コードとテストを書いて実行します。`.afk/tasks/003.md` は次のようになります。

```markdown
# 空文字と空白だけの値を弾く検査スクリプトとテストを作る

`fixtures/sample.json` を読み、`id` または `value` がないとき・空文字のとき・空白だけのときはエラーにする。

## Acceptance

- 正しい `fixtures/sample.json` では終了コード 0 で通ること
- `id` または `value` が空文字・空白だけのときは 0 以外で終わること
- 自動テストで正常・空文字・空白だけの3パターンがすべて通ること

## Result

`python3 -m unittest discover -s tests` を実行し、3件すべて成功したことを確認。
```

タスクを終えるとき、エージェントは確かめた完了条件の番号（1始まり）を渡して `finish_task` を呼びます。

```json
{
  "plan_id": 1,
  "task_id": 3,
  "attempt": 1,
  "verified": [1, 2, 3]
}
```

AFK は次の3つを確かめてから `#003` を `Done` にします。
- `## Result` より上の文章が、確定したときから一文字も書き換えられていないこと。
- 3つの完了条件すべての番号（`[1, 2, 3]`）が揃っていること。
- `## Result` に結果が書かれていること。

最後に、エージェントがプラン自身（`001-r002.md`）の完了条件も確かめて `## Result` を書き、`update_plan(finish)` を呼ぶと、プラン全体が `Done` になります。

Claude Code や Codex では、ターンの終わりに次の1行が出ます。

```text
AFK · JSON fixture & verifier [Done] · 2/2 complete
Plan complete
```

---

## ステップ 7: セッションを閉じて、別セッションから再開する

セッションをまたぐ動きも試してみましょう。別の作業の途中で **ターミナルを閉じるか新しいチャットを開き**、もう一度 AFK を呼びます。

```text
/agent-flow-kit:afk さっきのプランの続きを進めて
```

1. `open_plan`（番号なし）で、最近のプラン一覧が `.afk/afk.db` から読み出されます。
2. 該当の `plan_id` で `open_plan` を呼ぶと、前のチャット履歴がなくても、いまの計画ファイル・未回答の質問・次にやるべきことがすぐ分かります。
3. もし前のセッションがタスクを作業中（`Doing`）にしたまま終わっていたときは、前のセッションが止まっていることを確かめたうえで `start_next(plan_id: ..., take_over: true)` を呼び、番号（`attempt`）を `1` から `2` に進めて引き継ぎます。

---

## ここで確かめたこと

- **依頼も計画も `.afk/` に残る：** チャットが流れても消えません。
- **迷うところは質問して止まる：** 答えるまで先に進まず、回答は `## Answer` に残ります。
- **`Backlog` で計画だけ先に見られる：** 納得してから作業を始められます。
- **途中で条件が増えても、終わった作業は無駄にならない：** 未完了の分だけを組み直せます。
- **条件と結果が揃わないと完了にならない：** 条件の書き換えも検知されます。
- **新しいセッションからすぐ続きができる：** `.afk/` を読むだけで復帰します。
