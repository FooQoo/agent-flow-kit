# ワークスペースの設定と状態の保存

プラグインの導入手順は [インストールガイド](../../../website/ja/guide/index.md)を参照してください。

## プロジェクトフォルダが決まる順番

1つの `afk` プロセスが扱うプロジェクトは、起動してから終わるまで **1つだけ** です。次の順番でフォルダを決めます。

| 順番 | 見に行く場所 | 主な使われ方 |
| --- | --- | --- |
| **1** | 引数 `--root <directory>` | プロジェクト単位の MCP 設定 |
| **2** | 環境変数 `AFK_PROJECT_ROOT` | スクリプトや CI |
| **3** | 環境変数 `CLAUDE_PROJECT_DIR` | Claude Code プラグイン |
| **4** | `record_request` / `open_plan` の `workspace` 引数 | Codex プラグイン、Antigravity 共通設定（`AFK_NEEDS_WORKSPACE=1`） |
| **5** | MCP の `Roots` 機能（最大 800 ms 待機） | ローカルの `file://` ルートを1つ返すクライアント |
| **6** | 起動時のカレントフォルダ（`AFK_NEEDS_WORKSPACE` がないときだけ） | リポジトリ直下での直接起動 |

### 間違った場所に `.afk/` を作らないための守り

- **OS のルートやホーム、プラグイン置き場は拒否します：** `/`、`HOME` / `USERPROFILE`、および `PLUGIN_ROOT` / `CLAUDE_PLUGIN_ROOT` の中では `"no project directory; configure AFK_PROJECT_ROOT"` と出して止まります。
- **MCP Root が複数あるときは勝手に選びません：** 起動フォルダがそのどれかと一致するときだけ採用し、分からなければ `AFK_PROJECT_ROOT` の指定を求めます。
- **途中で別プロジェクトには切り替えません：** プロジェクト A で動いているセッションにプロジェクト B の `workspace` を渡すとエラーになります。別のプロジェクトで作業するときは、新しいセッションを開いてください。

## `.afk/` の Git 管理

AFK を動かすと、プロジェクト直下に `.afk/` が作られます（Unix 系 OS ではフォルダ権限 `0700`、ファイル権限 `0600`）。

```text
.afk/
├── afk.db              # 状態・順番・ハッシュ・履歴（SQLite）
├── requests/NNN.md     # あなたの依頼文
├── plans/NNN-rMMM.md   # 版ごとの計画と全体の結果
├── tasks/NNN.md        # 各タスクの内容・完了条件・結果
└── questions/NNN.md    # エージェントからの質問とあなたの回答
```

`.afk/` を Git に入れるかどうかは、プロジェクトのやり方に合わせて選べます。

| やり方 | 向いている場面 | 気をつけること |
| --- | --- | --- |
| **`.gitignore` に入れて除外する** | 自分の手元の補助として使い、Git にはコードとテストだけを残したいとき。 | 次のセッションで続きを再開できるよう、手元の `.afk/` フォルダ自体は消さずに残しておきます。 |
| **`.afk/` ごと Git にコミットする** | チームで計画を引き継いだり、PR で「どんな計画と確認を経て実装したか」も一緒に見たいとき。 | 作業が止まっている状態で **`afk.db` と全 `.md` ファイルを必ず一式まとめて** コミットしてください。依頼文や結果に秘密情報を貼らないよう注意します。 |

> [!IMPORTANT]
> `afk.db` と `.afk/` の中の Markdown ファイルは、ハッシュ値でお互いの内容が合っているか確かめています。Markdown だけがあって `afk.db` がない状態になると、ファイルを壊さないために起動を止めます。コピーやコミットをするときは、必ず `.afk/` フォルダ丸ごと扱ってください。
